# Contributing to Code Skater

Thanks for helping make the game better. This page explains how changes get in.

## How it works

1. **Fork** the repository and create a branch for your change.
2. Make the change and run the checks below.
3. Open a **pull request** that says what you changed and why. Screenshots help for anything visual.
4. The maintainer reviews every pull request. Nothing is merged without the maintainer's approval,
   and the maintainer may ask for changes or decline a pull request.

Only the maintainer can merge into `main` or change the repository. Opening a pull request never gives
anyone write access.

The automated checks on a pull request from a new contributor only start after the maintainer
approves them to run. They run with read-only permissions and no secrets.

## Checks to run before you open a pull request

```sh
npm ci
npm run typecheck
npm run lint
npm test
npm run build
npm run check:parody
npm run check:size
```

`npm run test:e2e` runs the browser smoke tests (it needs Playwright's Chromium:
`npx playwright install chromium`).

## Ground rules

These keep the game safe to play and easy to review. Pull requests that break them are declined.

- **No downloaded assets or network calls.** All geometry, textures and audio are generated by code.
  No CDN files, fonts, analytics, trackers, ads or remote URLs of any kind.
- **No new dependencies** without discussing it in an issue first.
- **No secrets** (keys, tokens, passwords) anywhere in the repository.
- **Names:** use the made-up parody names from `src/data/brands.ts`. Real company or person names
  may only appear in that file (`tests/brands.test.ts` enforces it). Never add licensed skate game
  names, real pro skaters, or licensed music.
- **No em dashes in text players see.** Use periods, commas or colons.
- **No magic numbers:** tunable values live in `src/core/tuning.ts` or `src/core/tuning/*.ts`.
- **Keep the sim deterministic:** no rendering imports, `Math.random` or wall-clock time in
  `src/sim/**`.
- Keep changes focused: one idea per pull request is easiest to review.

`AGENTS.md` lists the full house rules (it is written for AI coding agents too), `DESIGN.md` is the
game design and `ARCHITECTURE.md` maps the code.

## Reporting bugs and ideas

Open an issue with what you did, what you expected and what happened. Include your browser, whether
you play with a controller or keyboard, and a screenshot if you can.

Security problems go through [SECURITY.md](SECURITY.md), not public issues.
